# AGENTS.md — 工作区指令（doc）

本目录下所有涉及「基于源数据生成 / 填充 / 修改 Office 文档」的任务，必须遵循下方 Skill「文档生成规范」。该 Skill 沉淀自本项目实际执行经验，属强制约束；与用户即时指令冲突时，以用户即时指令为准。

---

## Skill: 文档生成规范（doc-generation-norms）

### 触发时机
- 需要把一批数据（测试用例、清单、台账等）按模板生成 Excel / Word 文档；
- 需要修改既有文档（改列、删行、修值、追加内容）或把多个数据源合并进目标文件；
- 需要对 xlsx / docx 做内容级修复（如纠正错值、清理串行旧值）。

### 核心原则（不得违反）

1. **内容逐格照搬，禁止改写**
   - 目标单元格的值必须与源数据逐字符一致（含换行、前后空格、标点、序号、原文里的错误/串行值）。
   - 不允许做任何"纠正、规范化、清洗、去重、补默认值"式的改写，除非用户明确授权。
   - 示例（本项目教训）：源表中「交易/功能名称」存在串行旧值（类需求分析流程/移动端登录/移动端首页），只能原样复制或在用户确认后处理，不得自作主张改值。

2. **只动目标范围，目标之外的数据零改动**
   - 仅修改用户指定的单元格 / 行 / 列 / 页。
   - 表头、页签、其他行、其他页、说明页统计等一律保持原样；必要时先快照，事后证明"差异为 0"。

3. **样式零改动**
   - 不修改任何既有样式：字体、字号、颜色、加粗、边框、对齐、数字格式、行高、列宽、冻结、下拉框（数据有效性）。
   - 新增内容如需样式，使用最小可行样式，并明确告知；必要时采用"只改 XML 中目标 `<c>` 的 `<v>` 值、保留 `s=` 样式属性"的手术式写法，保证其余字节不动。

4. **模板格式保持一致**
   - 填充模板时，目标文件的列结构、字段对应关系与既有模板/既有行完全一致。
   - 已确立的映射规则不得擅自改变（例如：功能名称←交易/功能名称、测试点←用例名称、案例性质按"正例/正用例→001-正案例、反例/反用例→002-反案例"映射、是否涉账按分析填"002-否"等）。

5. **预选项分析填充，不确定则留空并报告**
   - 带下拉/预选项的列，可依据源数据做有依据的映射后填写（分析结果需在交付时标注"分析推断，需复核"）。
   - 没有把握的列一律留空，不猜、不填默认值；交付时逐列说明"哪些列未处理、为什么"。

6. **不明确先确认**
   - 规则存在二义、或一次改动影响大量行/列时，先向用户确认（给出选项与推荐项），不擅自决定。

7. **剔除非数据行（并说明）**
   - 模板说明行（如 `/*…必输*/`）、示例行（如"二代央行评级系统 BHPL01单位签约"样例）、表头行不属于数据，应剔除并在交付中说明剔除范围。

8. **富文本 / 多行文本的读取**
   - 富文本单元格用权威接口读取其纯文本（`p.body.dataStream`）；去掉数据流末尾**唯一一个段落标记**（`\r\n` 或 `\n`/`\r`），但单元格文本自身真实存在的结尾换行必须保留。
   - 换行符统一归一为 `\n`；不要额外裁剪首尾空白以外的字符。

9. **破坏性修改先备份**
   - 修改用户源文件前，先复制一份备份（命名如 `xxx_修改前备份.xlsx`），交付时告知备份位置，用户确认后可删。

10. **交付前逐格校验**
    - 改动后必须独立校验（用 XML 解析或权威读取，不能只依赖写入时的回读）：
      - 目标单元格与源数据逐格比对，差异 = 0；
      - 目标之外的区域与改前快照逐格比对，差异 = 0；
      - 行数 / dimension / 页签 / 下拉框范围与预期一致；
      - 共享字符串索引无越界、各 XML 部件良构、Excel 可正常打开（不触发修复提示）。

### 执行工作流

1. 读源：列出文件、页签、表头、列结构、数据有效性（下拉）；确认锁定状态。
2. 定映射：明确"源列 → 目标列"对应关系；不确定项列入待确认清单。
3. 快照：对目标文件改前状态做备份/快照（供事后零差异证明）。
4. 写入：只写目标范围；空值用 `{}` 不落格；富文本按原则 8 取纯文本。
5. 校验：按核心原则 10 全量校验。
6. 汇报：列出 ——
   - 处理了什么（位置、行数）；
   - 留空未处理的列及原因；
   - 分析推断填写的列（需用户复核）；
   - 剔除的非数据行；
   - 备份文件位置；
   - 任何假设 / 需要用户确认的点。

### 反例（本项目踩过的坑）

- ❌ 用 `getValues(true)` 读富文本单元格，导致多行/富文本内容丢失 —— 应改用 `getCellDatas()` 或直接解析 XML。
- ❌ 给已有文件追加行后导出，下拉框范围被截断、列宽/行高被改写 —— 应保留模板结构（下拉范围、列定义、行高）。
- ❌ 自建"说明页/序号列/来源列"或重排行序 —— 除非用户明确要求。
- ❌ 把源表填写串行的值"顺手纠正" —— 只能原样复制或先确认。
